# Диагноз Dr. Unslopovich

**Вердикт:** монитор показывает показатели, но пока заставляет оператора отдельно выяснять, можно ли им доверять.

Stack: React 19 / TypeScript / Vite, TanStack Query и Table, ECharts, собственный CSS. Платформа: рабочее веб-приложение.

Reviewed: вход, обзор и монитор; переход в карточку проверен только для оценки сохранения контекста. Задачи: найти животное и определить, какие наблюдения требуют внимания. Проверка по исходникам, не по отрисованным экранам. HTTP доступность localhost:8080 подтверждена curl: 200. Предыдущее ограничение пользователя «без установки браузера» сохранено.

Chart отсутствует. Контекст взят из frontend/AGENTS.md, docs/design/interface.md, кода и продуктовых ограничений. Зафиксированную зелёную палитру, название «Стадо» и учебную маркировку сохранять. Принятых исключений в chart нет.

## Critical

### C1. Сбой загрузки одновременно представлен как отсутствие данных

- `frontend/src/monitor.tsx:212–216`: ErrorBox выводится отдельно, затем при data=undefined/isPending=false показывается «Животные не найдены». В этом же случае Pager получает total=0.
- `frontend/src/monitor.tsx:302–315`: после ErrorBox история без data попадает в «Нет показаний за выбранный период».
- `frontend/src/App.tsx:39`: ошибка /auth/me, включая 5xx/сетевой сбой, ведёт к форме входа, хотя отсутствие сессии не установлено.

**Кому мешает:** оператор может принять недоступность сервера за пустое стадо или отсутствие измерений; пользователь со сбоем проверки сессии повторно вводит пароль без объяснения.

**Исправление:** взаимоисключающие состояния pending → error → success-empty → success-data. При сбое фонового обновления сохранять предыдущие данные с временем успешного обновления и явным предупреждением. «Повторить загрузку» рядом с ошибкой. Форму входа показывать при подтверждённом 401; ошибку связи с сервисом — отдельным состоянием. Это рекомендация для последующей функциональной задачи, не изменение в рамках review.

**Приёмка:** 503 /cows не показывает «не найдены» и «0 записей»; 503 истории не показывает пустой период; 503 /auth/me не выдаётся за разлогинивание.

## Noticeable

### N1. Возвращение из карточки теряет рабочую выборку

`frontend/src/monitor.tsx:131,337`: карточка открывается без returnTo, ссылка «Вернуться к монитору» всегда ведёт на /monitor без query. Обычная кнопка браузера «Назад» может восстановить предыдущий URL; проблема именно в ссылке приложения.

**Исправление:** сохранить исходный путь с q/status/sort/page и выбранной фермой, восстанавливать позицию прокрутки; предусмотреть fallback /monitor при прямом открытии карточки. Не переименовывать и не переносить существующий контроль без согласования.

**Приёмка:** поиск → страница 2 → карточка → ссылка возврата восстанавливает выборку и страницу. Переход по прямой ссылке тоже работает.

### N2. Таблица не показывает давность результата анализа

`frontend/src/monitor.tsx:140–155`: badge показывает status, но analysis_at и analysis_delayed в таблице не используются. Устаревание отдельных измерений уже обозначено — это стоит сохранить. Состояние WS отдельно не говорит о свежести измерений или результата модели.

**Исправление:** под результатом анализа выводить время последнего завершённого окна; при analysis_delayed пояснять задержку. У значений оставить единицы и независимую свежесть. Отсутствие аномалии не переименовывать в «здорово» и не вычислять медицинские пороги в UI.

**Приёмка:** при недоступном ML пользователь видит, что результат относится к прошлому окну, даже если транспортное соединение активно.

### N3. Статистику обзора трудно превратить в действие

`frontend/src/monitor.tsx:42–94`: количество аномалий и уведомлений отображается в article без перехода; дальше следуют ещё распределение тех же статусов, общий график и поясняющий баннер. Данные настоящие, проблема в приоритете и доступе к нужной выборке.

**Предложение, требующее согласования:** сделать «Аномалии» переходом на существующий /monitor?status=anomaly, «Открытые уведомления» — на соответствующую выборку, не менять смысл агрегатов. Вместо рекламоподобного баннера и части повторной статистики дать рабочий список внимания с ID животного, временем и переходом в карточку. Сначала уточнить, что считать очередью: аномалии, неподтверждённые уведомления или оба типа; не объединять состояния молча. Не менять стартовый маршрут без согласования.

### N4. Обновления могут мешать поиску и стабильности таблицы — требует профилирования

`frontend/src/App.tsx:147–167`: любое WS-событие помечает все запросы кроме me устаревшими, до одного раза в секунду. `frontend/src/monitor.tsx:105,119,189`: каждый символ создаёт новый URL и ключ запроса; placeholderData не задан, запрос не использует AbortSignal. `frontend/src/components.tsx:58–89`: смена points пересоздаёт график.

**Риск:** лишние запросы, промежуточные loading-состояния, изменение высоты страницы, сброс графического контекста. Фактические задержки не измерены.

**Рекомендуемая отдельная инженерная задача:** сохранить предыдущую страницу до получения новой с отметкой обновления; поиск отправлять после короткой паузы (ориентир 250–300мс), отменять устаревшие запросы, не добавлять запись истории браузера на каждый символ. Обновлять только затронутые данные, сохраняя REST-resync при reconnect/refocus. ECharts инициализировать один раз, данные менять через setOption. Такие изменения затрагивают data flow, поэтому не делать их как косметическую правку по этому отчёту.

### N5. Контраст и мобильный статус требуют исправления

Расчёт sRGB-контраста по литералам CSS, без браузера:

| Текст | CSS | Контраст | Ориентир |
|---|---|---:|---:|
| Подписи карточек | style.css:362, #7b8d80 на белом | 3,52:1 | 4,5:1 |
| Заголовки таблицы | style.css:477, #708174 на #f8faf8 | 3,94:1 | 4,5:1 |
| Устаревшее значение | .stale, #a87835 на белом | 3,89:1 | 4,5:1 |

`style.css:919`: текст соединения получает font-size:0, остаётся только цветная точка. На видимом мобильном экране статус зависит от цвета. Многие подписи/элементы пагинации уменьшены до 11–12px. Focus есть, но его цвет на белом даёт лишь около 1,91:1 — стоит проверить различимость при клавиатурной работе.

**Исправление:** затемнить служебный текст в пределах существующей палитры; обычные рабочие подписи ориентировать на 14–16px. Оставить короткий текст «На связи»/«Нет связи»; увеличить контраст focus. Проверить 375/768px и 200% zoom перед утверждением размеров. Точную отрисовку сейчас не проверяли.

### N6. Мобильное меню визуально скрыто, но доступно клавиатуре

`frontend/src/style.css:895`; `frontend/src/App.tsx:191,237`: translateX не убирает ссылки из tab order. Кнопка всегда называется «Открыть меню», даже когда меню открыто; aria-expanded/aria-controls и обработка Escape не предусмотрены.

**Исправление:** синхронизировать видимость и доступность (inert/эквивалент для закрытого меню), aria-expanded/controls, возврат фокуса и Escape. Оставить существующие пункты и маршруты; менять структуру навигации для этого не нужно. На коротких экранах проверить прокрутку самого sidebar.

### N7. График не имеет доступного эквивалента

`frontend/src/components.tsx:90–96`: canvas представлен как img с названием метрики, но данные прочитать нельзя. Это ограничивает основную задачу просмотра истории для screen reader.

**Исправление:** рядом с графиком дать раскрываемую таблицу «Данные графика» с временем, значением, единицей и пропусками из того же ответа API. Не подменять отсутствие измерения нулём. Экспорт не обязателен для решения этой проблемы.

## Minor

- `frontend/src/App.tsx:80`: число 200 в форме входа задано статически, хотя число зарегистрированных животных меняется. Убрать число из приветственного оформления либо явно назвать его конфигурацией демонстрационного примера; не раскрывать реальную статистику до входа ради декора.
- `frontend/src/monitor.tsx:132`, `App.tsx:198–219`: Unicode-ромб возле каждой коровы и разностильные символы навигации не помогают различать объекты. При следующем согласованном проходе использовать единый набор простых inline SVG без новой зависимости; декоративные элементы скрыть от screen reader. Не менять логотип.

## Ask first

- Структура первого экрана: приоритет очереди внимания вместо части сводки/баннера. Меняет композицию и рабочие акценты; согласовать определение очереди, сохранив навигацию и агрегаты.
- Существующий контроль возврата из карточки: предложено восстанавливать исходный URL/ферму/прокрутку, сохранив надпись и расположение. Изменение поведения часто используемого контроля требует согласования.
- Корректировка сетевого обновления/поиска — функциональная инженерная задача, не стилистическая правка. Бизнес-правила, статусы и расчёты остаются за backend.

## Worth keeping

- Зелёная идентичность и название уже зафиксированы: не нужно заменять их новым универсальным шаблоном.
- Таблица остаётся таблицей; серверные сортировка/фильтрация/пагинация, query-параметры URL — правильная основа. 25 строк на странице не требуют виртуализации ради галочки.
- Реальные button/link/select, подписи полей, autocomplete логина/пароля, видимый focus, разрешённый zoom.
- Единицы метрик, отдельные no_anomaly/anomaly/insufficient_data, маркировка синтетики и отсутствие диагностических обещаний.
- Разрывы графика на отсутствующих данных и REST-resync после reconnect.

## Порядок улучшений

1. Исправить правдивость состояний загрузки/ошибки/пустой выдачи и поведение при ошибке проверки сессии.
2. Восстановление контекста монитор → карточка → монитор, время анализа прямо в таблице.
3. Контраст, подписи соединения, доступность меню и табличная альтернатива графику.
4. Согласовать рабочую композицию обзора; уменьшить повторные пояснения, декоративные рамки и капительные надзаголовки. Не менять палитру, название, маршруты и смысл чисел.
5. Отдельно профилировать поиск и live-обновления, затем исправить подтверждённые задержки/скачки.
